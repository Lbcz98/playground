# T05 — Generated guides and drift check

**Goal.** The token reference and the rules guide that designers' Claude Code reads are generated from `tokens/tokens.json` and `rules.ts`, and cannot drift.
**Requirement.** R6 (Q20). **Depends on.** T00. **Wave.** 1 (parallel with T01, T06).

## Touches
`scripts/build-guides.ts` (+ `.test.ts`, new), `src/shared/export/commentGrammar.ts` (new), `src/shared/export/fromTsx.ts` (import the `@deviation` pattern from the new module, nothing else), `web/protos/generated/tokens.md` and `rules.md` (generated, committed), `package.json`, `web/protos/CLAUDE.md` (replace the pointers with links to the generated files, nothing else), `scripts/build-tokens.ts` only if folding the check there.

## Read first
`scripts/build-tokens.ts` and `scripts/tokens/compile.ts` (how `--check` works), `tokens/tokens.json` and `tokens/README.md`, `src/styles/global-tokens.ts` and `src/design-system/tokens.ts` (the names a screen actually writes), `rules.ts`, `deviations.ts` (`ruleScope`), `README.md` sections "token tier rule" and design rule 6.

## Requirements
1. `npm run guides:build` writes both files; `npm run guides:check` exits 1 when a committed file differs from regeneration. Output is deterministic: stable ordering, no timestamps. Header: `<!-- GENERATED by scripts/build-guides.ts from tokens/tokens.json and src/shared/design-system/rules.ts. Do not edit; run npm run guides:build. -->`.
2. **`tokens.md`**: every non-core token (semantic and layout tiers; every group in `tokens.json`, including typography and motion) with its group, its path, its resolved value, and the name a screen writes when that differs from the path (derive it from the kit's prop types; do not hand-write a mapping). **Core tokens are never listed.**
3. **`rules.md`**: every rule in `rules.ts`, grouped law / pattern / convention, with id, title, statement verbatim and `appliesTo` when present. Then a "How to declare" section generated from `commentGrammar.ts`: `@deviation` with node vs screen placement (from `ruleScope`). T03 adds `@reuse` and `@proposal` to the same module and regenerates.
4. **Drift fails the build:** `npm run tokens:check` exits 1 on guide drift (chain or fold, the implementer chooses and documents it), and a vitest test fails when the committed guides are stale, so `npm test` fails too (design rule 6).
5. `web/protos/CLAUDE.md` links to the two generated files instead of pointing at `tokens/tokens.json` and the source.

## Acceptance criteria
- **AC1** Running `guides:build` twice produces byte-identical files; `guides:check` exits 0 right after.
- **AC2** In a scratch copy, change one value in `tokens.json` → `guides:check` and `tokens:check` exit 1, and the vitest test fails.
- **AC3** In a scratch copy, add a rule to `rules.ts` → the same three fail. Remove it → all pass again.
- **AC4** A script asserts every `rules.ts` id appears in `rules.md`; and no core token path or name appears anywhere in `tokens.md` (the test builds the core list from `tokens.json`).
- **AC5** Five tokens picked at random from `tokens.md` are each accepted by a kit prop type (the verifier writes a tiny tsc probe in a scratch copy).
- **AC6** `fromTsx.test.ts` and `checkLaws.test.ts` are green and unmodified; `lint:tokens` is green.
- **AC7** Gates green, test count not lower.

## Mutation probes
In a scratch copy, reorder the entries of `rules.ts` and the keys of `tokens.json` → `guides:check` must still exit 0 (the output is sorted, so input order must not matter). If it exits 1, the generator depends on input order and AC1 is not really met.

## Out of scope
Rewriting the hand-written part of `CLAUDE.md` (T08). Generating anything for imported design systems.

## Report back
Status, commit sha, how drift is wired into `tokens:check`, how screen-facing token names are derived, the generated file sizes.
